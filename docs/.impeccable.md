# Impeccable Design Context

> This file is the authoritative design context for the Endfield Architect project.
> It was gathered through codebase analysis and user interviews.
> All design decisions should align with this context.

## Design Context

### Users

- **Who they are**: Arknights: Endfield players planning AIC factory production across multiple sites
- **Context**: Mixed usage — casual 5-15 minute planning sessions AND deep 30+ minute optimization dives
- **Job to be done**: Enter production goals → get facility counts and material requirements → save/share plans via URL
- **Emotional context**: They want clarity and confidence, not overwhelm. The tool should feel like a professional planning console — organized, trustworthy, and capable.

### Brand Personality

- **Three-word personality**: Industrial Precision + Arknights-Authentic + Data-Driven Efficiency
- **Voice**: Technical but approachable. Industrial without being cold. The UI speaks like an operational planning system, not a consumer app.
- **Tone**: Calm confidence — clear hierarchy, no noise, every element earns its place.
- **Emotional goals**: Confidence (clear data presentation), Control (predictable interactions), Capability (powerful for deep dives, quick for casual use)

### Aesthetic Direction

- **Visual tone**: Dark industrial with tactical accents. Matches the Arknights: Endfield game UI aesthetic — not generic dark mode, not corporate dashboard.
- **Reference**: Arknights: Endfield official game UI (industrial, high-contrast, functional)
- **Anti-references**:
  - Colorful/playful designs — this is industrial, serious
  - Generic AI chatbot UIs (round cards, purple gradients, excessive border-radius)
  - Corporate enterprise software (blue business dashboards)
- **Theme**: Dark mode only for now (matching game UI). May add light mode later.
- **Density vs. breathing room**: Operational dashboard feel — generous spacing in control areas, dense where data matters (results tree, metrics).

### Design Principles

1. **Arknights-Authentic Industrial**
   - Match the game's visual language: dark backgrounds, high-contrast yellow accents, sharp edges, technical typography
   - Use the established color system: `#191919` deep bg, `#fffa00` accent, `#e04040` error, `#c8860a` warning
   - Grid/technical background patterns where appropriate

2. **Operational Clarity**
   - Clear visual hierarchy: controls in organized panels with distinct zones
   - Generous spacing in control areas (GoalInput, PlannerTools) — these are the primary interaction zones
   - Dense, information-rich display in results areas (ResultsTree, metrics) — data is the payoff
   - Dashboard feel: breathing room between sections, clear separation of concerns

3. **Functional with Purposeful Flare**
   - Subtle panel/micro animations already in place — keep these (panel-enter, tree-node reveals)
   - Add ambient elements sparingly: status indicator pulses, subtle glows on active elements
   - No gratuitous animation — every motion should serve a purpose (feedback, orientation, or atmosphere)
   - Interactive feedback on buttons and controls — hover states, press states, transitions

4. **WCAG AA Compliant with Color Blindness Awareness**
   - Status colors (error/warning/ok) must be distinguishable without relying solely on hue
   - Error: `#e04040` (red) — paired with AlertCircle icon
   - Warning: `#c8860a` (amber) — paired with AlertTriangle icon
   - OK: `#40c070` (green) — paired with Check icon
   - Always use icon + color + text together for critical states
   - Respect `prefers-reduced-motion` — disable ambient animations, keep functional transitions

5. **Mixed-Usage Friendly**
   - Quick session: clear empty state guidance, fast goal entry, instant results
   - Deep session: URL persistence for sharing/saving, expandable detail in results tree, comprehensive tool panels
   - No mode switching — the same interface scales from casual to power use

### Color System (Established)

```
Background Deep:     #191919  (--color-bg-deep)
Background Surface:   #222     (--color-bg-surface)
Background Elevated: #2e2e2e  (--color-bg-elevated)
Background Input:    #1f1f1f  (--color-bg-input)
Text Primary:        #fff     (--color-text-primary)
Text Secondary:      #b3b3b3  (--color-text-secondary)
Text Muted:          #777     (--color-text-muted)
Border:              #333     (--color-border)
Accent:              #fffa00  (--color-accent)
Accent Hover:        #efe701  (--color-accent-hover)
Accent Border:       #fff500  (--color-accent-border)
Status Error:        #e04040  (--color-status-error)
Status Warning:      #c8860a  (--color-status-warning)
Status OK:           #40c070  (--color-status-ok)
```

### Typography (Established)

```
Display (headings):  Montserrat, bold, uppercase, letter-spacing: 0.1em
Sans (body):         Barlow, regular weight
Mono (data/metrics): JetBrains Mono, for numbers and technical data
```

### Component Patterns (Established)

- **Panels**: Dark surface with left accent border, gradient header, collapse/expand capability
- **Buttons**: `btn-tactical` — display font, uppercase, letter-spaced, accent color
- **Inputs**: `input-terminal` — dark bg, accent on hover/focus
- **Steppers**: For numeric input with +/- controls
- **Tree nodes**: Nested rows with expand/collapse, depth indicators, facility/count/rate/metrics
- **Status indicators**: Dot + color + icon always together

### Motion Guidelines

- **Functional motion**: Panel reveals, tree node stagger, form transitions — keep these
- **Ambient motion**: Status dot pulse, originium diamond echo — keep but honor reduced-motion
- **Interactive feedback**: Button hover/focus states, input focus glows — add where missing
- **Reduced motion**: All ambient/decorative animations disabled via `prefers-reduced-motion: reduce`
